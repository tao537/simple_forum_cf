================================================================================
0. 结论速览
================================================================================
- uploadImage 原先只吃本地路径；后端上传接口（/api/posts/upload 与
  /api/game/posts/upload）都要求 multipart 文件字节 + file.type 是 image/*，
  没有任何「传 URL 让我去拉」的参数 ⇒ URL 直传不可行，必须下载到本地再上传。
- 改造后行为：URL 先直连下载（10s），失败再走代理下载（30s，读 .env 的 HTTPS_PROXY），
  下载缓存 /tmp/publish-game-cache/；单张失败只跳过不中止；每条最多 5 张。
- 顺带修掉一个潜伏 bug：原 uploadImage 用 new Blob([buf])（无 MIME），
  实测被后端 400「只能上传图片」拒绝 ⇒ 带截图支路按原代码必然失败。已改为
  按魔数判类型并写入 Blob type。
- 关键网络结论：Node 只在「进程启动时」读 NODE_USE_ENV_PROXY，进程内 setenv 无效；
  所以代理下载用子进程 + 启动前注入 env（与 run-with-proxy.sh 同路数）。
  同一结论也说明 fetch.mjs 的 applyProxy() 实际没让代理生效（已记入项目报告已知问题 7）。

2. 实验一：NODE_USE_ENV_PROXY 的生效时机（决定性实验）
================================================================================
方法：起一个「假代理」打印收到的 CONNECT；每个用例先用 env -u 清掉全部大小写代理变量，
      再用「假代理是否收到 CONNECT / 请求是否成功」判定代理有没有生效。

  用例                                         结果                                   判定
  D1 启动前 仅大写 HTTPS_PROXY=假代理           假代理收到 CONNECT，请求失败            代理生效
  D2 启动前 仅小写 https_proxy=假代理           假代理收到 CONNECT，请求失败            代理生效
  D3 启动前 大小写都设（= fetch.mjs 的做法）     假代理收到 CONNECT，请求失败            代理生效
  D4 进程内 setenv 后再 fetch（= applyProxy）   假代理 0 个 CONNECT，直连 200（0.9s）   代理未生效
  D5 启动前设 NO_PROXY=<目标域名>               假代理无 CONNECT，直连成功               排除规则生效
  T1 启动前 + 不可达代理(192.0.2.1) + 漏清小写   200（实走 shell 的 7892）              曾造成假阳性
  E  会话内 + 假代理(:9) + 漏清小写              200（同上）                             曾造成假阳性

结论：NODE_USE_ENV_PROXY 在进程启动时读取；进程内设置无效，且不存在「代理不可达就静默
      直连」的回退（假代理返回 502 时请求直接失败）。踩坑点：shell 里的小写 https_proxy
      会掩盖实验，必须大小写一起清。

4. 实验三：Blob MIME 对照（改造前后端行为）
================================================================================
同一个 36952 字节 JPEG，用真实论坛管理员账号登录（token 长度 193，不记录明文）后上传：

  A 现状写法 new Blob([buf])（无 type）：        HTTP 400 → {"message":"只能上传图片"}
  B 带 type   new Blob([buf],{type:"image/jpeg"}): HTTP 200 → {"url":"https://api.kuhai.de5.net/img/..."}

⇒ 原代码的「上传截图」无论本地还是远程都会 400，改造里必须补 MIME（已按魔数推断）。
