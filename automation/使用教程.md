## 一、5 分钟快速开始

前提：Node 已装好，代理（Clash，127.0.0.1:7890）在跑，ollama 在跑。`config.json` 只有
**第 3 步正式发布**才需要：本机这份**已填好**（文件存在，4 个账号字段 + 门禁密码都在，
顶层 `_TODO` 只留作状态备忘），2026-10-04 已用它真发成功一次（见 3.5）；换机器才需要按
2.3 重建并填。

```bash
cd /home/zhong/Desktop/project/simple_forum_cf/automation

# 1. 抓取候选（fetch.mjs 自带代理，无需包装脚本）
node fetch.mjs steam            # Steam 免费游戏
node fetch.mjs galgame          # galgame（需先配站点，见第五节）

# 2. 复核：生成 HTML + Markdown 报告，默认用 firefox 打开
node review.mjs steam

# 3. 发布：清单写进 queue/ 后，先空跑体检（不发帖、不动任何文件）
node publish-game.mjs --dry-run

# 确认无误后再去掉 --dry-run 正式发布 —— 这条会真的发帖，还需要 config.json（见 2.3）
# ⚠️ 不带参数时它会发 queue/ 里「全部」清单（现在 7 条）；只想发一条用 --file（见 3.4/3.5）
node publish-game.mjs
```

三步对应的产物：

| 步骤 | 读 | 写 |
|---|---|---|
| 抓取 | 网络（Steam API / 各 galgame 站点） | `candidates/<来源>-<日期>.json` |
| 复核 | `candidates/<来源>-<日期>.json` | `reports/<来源>-<日期>.html` + `.md` |
| 发布 | `queue/*.json` + `config.json` + ollama | 游戏站帖子 + `published/<清单名>.json` |

## 二、环境准备（只做一次）

### 2.1 Node 版本

```bash
node -v
```

- 抓取：Node 18+（只用内置 fs / path / url / fetch）。
- 但"让内置 fetch 真的走代理"依赖 `NODE_USE_ENV_PROXY`，这是 **Node 24+** 才有的行为。
  本机实测为 `v26.8.2`，没问题。

### 2.2 确认代理在跑

```bash
curl -s -x http://127.0.0.1:7890 https://www.google.com -o /dev/null -w "%{http_code}\n"
# 输出 200 = 代理正常；000 = Clash 没起或端口不对
```

### 2.3 准备 config.json（发布必需）

`config.json` 含账号密码，被 `.gitignore` 忽略，不会进 git。仓库里只有模板
`config.example.json`；**本机这份 `config.json` 已填好**（2026-10-04：4 个账号字段 + 门禁
密码都填了，`apiBase` / `siteBase` 用模板值，`network.proxy` 与 `cloudAi.apiKey` 留空；顶层
`_TODO` 写的是当前状态，不是待办），所以日常发布不必再 cp，只有文件丢失或换机器时才重建。

```bash
# 只在文件丢失（或换机器）时才需要重建
cp config.example.json config.json
```

⚠️ `config.json` 由 `JSON.parse` 严格解析（fetch.mjs:121 / publish-game.mjs:380），
**不能写 `//` 或 `/* */` 注释**，否则会报「config.json 解析失败」（退出码 1）——
想留提示就写到顶层 `_TODO` 字段里。

需要填的字段：

| 字段 | 说明 |
|---|---|
| `siteBase` / `apiBase` | 游戏站与 API 地址，模板里已填好 |
| `game.gatePassword` | 游戏站门禁密码（模板里已填） |
| `game.adminUsername` / `adminPassword` | 游戏站管理员账号（首个注册的那个），**发帖必需** |
| `forumAdmin.username` / `password` | 论坛管理员账号，**仅上传截图时需要**；不发截图可留空 |
| `ollama.model` | 本地生成文案的模型，模板是 `qwen2.5:7b` |
| `cloudAi.apiKey` | 云端润色（DeepSeek/OpenAI 兼容），**留空则跳过润色** |

> 本机这份这 6 行里的字段 2026-10-04 已全部就位（4 个账号字段填了真实值，其余保持模板值/
> 留空），并且当天真发成功过一次——所以除非文件丢了或换机器，你不用再碰这张表。

可选：想固定代理端口就填 `network.proxy`（文件里已预留该字段，值为空字符串；留空＝用内置
默认 `http://127.0.0.1:7890`）：

```json
{
  "network": { "proxy": "http://127.0.0.1:7890" }
}
```

### 2.4 确认 ollama 在跑

```bash
ollama list                  # 服务默认 http://localhost:11434
```

`config.json` 里 `ollama.model` 写的模型必须出现在这个列表里，否则发布时会在
"本地模型生成文案"这一步失败。

### 2.5 可选：.env 与 run-with-proxy.sh

`automation/.env` 已存在（`HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`），被 `.gitignore` 忽略。
`run-with-proxy.sh` 是给"本身不处理代理的脚本"（如 `publish-game.mjs`）包一层用的，
抓取并不需要它 —— 原因见第六节。

```bash
chmod +x run-with-proxy.sh    # 已可执行时无输出
ls -l run-with-proxy.sh       # 应含 x 权限
```

## 三、日常操作：抓取 → 复核 → 发布

### 3.1 第一步：抓取

```bash
node fetch.mjs steam
```

真实输出（2026-10-04，已有当天文件时）：

```

🚀 开始抓取来源：steam

📄 已存在 steam-2026-10-04.json（8 条），按 id 去重后追加

✅ 抓取完成：来源返回 8 条，新增 0 条，跳过重复 8 条，文件共 8 条
📊 本次入库 0 条，其中无图 0 条（建议人工复核）
📁 .../candidates/steam-2026-10-04.json
⏱️ 耗时 1.8 秒
```

**日期**：输出文件名用今天；补抓历史指定日期即可。

```bash
node fetch.mjs steam --date 2026-10-03
```

**网络**：默认走 `127.0.0.1:7890`。需要临时换端口或完全直连：

```bash
node fetch.mjs steam --proxy http://127.0.0.1:10809
node fetch.mjs galgame --no-proxy        # 国内站点直连，避免代理绕路
```

**看有哪些来源**：

```bash
node fetch.mjs list
```

`sources/` 下每个"含 `index.mjs` 的子目录"就是一个来源，新增来源**不用改 fetch.mjs**。

**输出位置**：`candidates/<来源名>-<YYYY-MM-DD>.json`（同一天重复跑会按 `id` 去重后追加，
不会重复写入，也不会覆盖已有内容）。

**几条必须知道的行为**：

- **无图不会丢**：没有任何封面/图片的条目照样入库，只在日志里打警告：无图的逐条 `⚠️` 提示，
  末尾再汇总一次（`✅` 行下面的「其中无图 M 条」）。用不用由你自己决定。
- **一条都没抓到就不写文件**：打印"⚠️ 本次没有抓到任何数据，未写入文件"，`candidates/`
  原有内容保持不动，退出码仍是 0。
- **出错就是出错**：网络不通、站点结构变了等会打印原因并**以退出码 1 结束，不静默重试**。
  按提示重跑，或用 `--no-proxy` / `--proxy` 换线路。

### 3.2 第二步：复核

```bash
node review.mjs steam
```

生成两份报告并**自动用 firefox 打开 HTML**：

- `reports/steam-2026-10-04.html` —— 卡片式浏览，顶部有"共 N 条 · 无图 M 条"统计
- `reports/steam-2026-10-04.md` —— VS Code 里 `Ctrl+Shift+V` 预览，方便复制文本

HTML 页功能：每张卡片显示封面、标题、标签、简介、id、原链接；

- 顶部筛选：**全部 / 仅有图 / 仅无图**（专门给上面说的"无图条目"用）
- 每条有"复制"按钮，一键复制 `id` 或 `url`（写 `queue/` 清单时可直接粘）

参数：

```bash
node review.mjs steam --date 2026-10-03   # 指定日期（默认取该来源最新的那个文件）
node review.mjs steam --no-open           # 只生成，不自动开浏览器
xdg-open reports/steam-2026-10-04.html    # 之后手动打开
```

### 3.3 第三步：发布

发布脚本是 **`publish-game.mjs`**（不是 `publish.mjs`），它读的是 **`queue/`** 目录。
（`drafts/` 目前是空目录，脚本不读它，可无视。）

**3.3.1 写游戏清单**

参考 `queue/_example-game.json`，每个游戏一个文件，文件名随意：

```json
{
  "name": "游戏名",
  "panUrl": "网盘链接",
  "panCode": "提取码",
  "genre": "类型（RPG / 动作 / 冒险…）",
  "platform": "安卓 / PC",
  "tags": ["二次元", "单机"],
  "notes": "给 AI 的备注（汉化、MOD、版本），可省略",
  "screenshots": ["screenshots/xxx.jpg"]
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `name` | **是** | 游戏名，AI 写文案的依据 |
| `panUrl` | **是** | 网盘链接，会被原样写进正文 |
| `panCode` | 否 | 提取码 |
| `genre` / `platform` / `tags` | 否 | 给 AI 的补充信息，越多文案越准 |
| `notes` | 否 | 额外备注（汉化/MOD/版本），AI 只参考不照抄 |
| `screenshots` | 否 | 截图路径，**相对清单文件所在目录**；没有就删掉这个字段 |

> 代码里的硬规则（`publish-game.mjs` 的 `validateGame()`，正式发布与 `--dry-run` 共用同一套）：
> `name`、`panUrl` 缺任何一个，脚本会在**生成文案之前**就中止；`screenshots` 一旦写了就必须是数组，
> 且里面每个文件都必须在本地真实存在——正式发布会**先查完所有截图再登录上传**
> （避免登录后才发现缺文件、已经传了一半）。
>
> **`panCode` 留空不中止**：只要 `panUrl` 是网盘链接，帖子照发，但正文里会自动插入一段
> 「⚠️ 提取码暂缺，需要请在评论区留言」的说明，同时在 `queue/_no-code-warnings.json`
> 记一条待补码。想改这段文案，就在 `config.json` 里加 `noCodeNotice`（设为 `""` 则不插入）。
> 填「无需 / 不需要」表示该分享本来就不需要提取码，不告警。

- **文件名以 `_` 开头会被跳过**（`_example-game.json` 就是模板），可用来暂存草稿。
- 截图放 `queue/screenshots/`（该目录被 gitignore，不会提交；**空目录已建好**，直接放图
  即可；上传需要论坛管理员账号，也就是 `config.json` 里的 `forumAdmin`）。

**3.3.2 执行**

```bash
node publish-game.mjs                        # 处理 queue/ 里全部清单（正式发布）
node publish-game.mjs --dry-run              # 空跑：体检 + 预览文案，不发帖
node publish-game.mjs --file queue/xxx.json  # 只处理指定清单（可配 --dry-run）
node publish-game.mjs -h                     # 打印用法
```

脚本对每个游戏依次做 5 件事：

1. ollama 本地模型生成 `title` + Markdown 正文
2. （可选）云端 AI 润色 —— 仅当 `config.json` 的 `cloudAi.apiKey` 非空
3. （可选）截图上传到论坛 KV —— 仅当清单里有 `screenshots`
4. 过门禁 → 游戏站管理员登录 → 发帖
5. 清单移到 `published/`，并追加 `publishedAt` / `postId` / `postUrl` 三个字段

成功时打印 `✅ 已发布：<帖子地址>`。

**真发之前先空跑：`--dry-run`**（2026-10-04 新增，实测可用）

空跑会走完整流程里"只读"的那部分：解析清单 → 字段校验 → 逐张检查截图文件是否存在 →
调本地 ollama **真生成一份文案**并打印将要发出的字段，然后**跳过** 门禁 → 登录 → 截图上传 →
发帖 → 归档。它的四条保证：

- **不需要 `config.json`**（缺了只提示一句 ⚠️，照样继续）
- **不调用云端 AI**，不会因为练手花钱（本地 ollama 的电费不算）
- **不动 `queue/` 和 `published/` 里任何文件**（已实测：前后文件 sha256 完全一致）
- **总是以退出码 0 结束**——它是体检，不是门禁，`❌` 只提醒"正式发布会在这里中止"

```bash
node publish-game.mjs --dry-run                                   # 空跑 queue/ 里全部清单
node publish-game.mjs --file queue/_example-game.json --dry-run    # 空跑指定清单（_ 模板也能指定）
```

实测输出长这样：

```text
⚠️ 未找到 config.json（--dry-run 不需要它；正式发布前请先 cp config.example.json config.json 并填写账号）

🔍 --dry-run 空跑：共 1 个清单（不发帖 / 不上传截图 / 不归档 / 不调用云端 AI）

▶ .../automation/queue/_example-game.json
  名称：示例游戏：星穹铁道（这里换成真实游戏名）
  · 字段校验：✅ name / panUrl 齐全
  · 网盘：https://pan.baidu.com/s/1234567890　提取码：abcd
  · 截图 screenshots/game1-1.jpg：❌ 文件不存在（正式发布会中止）
  · 截图 screenshots/game1-2.jpg：❌ 文件不存在（正式发布会中止）
  · 本地模型生成文案（--dry-run 跳过云端润色）…完成
  · 将要说出的字段：
      title   = 【游戏推荐】星穹铁道：穿梭星轨，探索未知的世界！
      content = 探索多样的星轨，邂逅不同角色，开启一场奇幻之旅！
                （正文共 280 字，此处截断预览）
      images  = 2 张（上传后替换为论坛地址）
  · --dry-run：跳过 门禁 → 登录 → 发帖 → 归档，queue/ 与 published/ 均不改动

🔍 空跑结束：共 1 个清单，其中 1 个成功生成文案预览（空跑只体检、不阻断）
```

- 空跑要有文案预览，本地 ollama 得在跑（`ollama serve`，模型 `qwen2.5:7b`）；
  ollama 没起时会打印 `❌ ...` + 一行提示，其余检查结果照常输出。
- **参数写错不会被容忍**：未知参数（如 `--bad-arg`）、`--file` 后面没跟值、
  `--file` 指向不存在的文件，都会打印完整用法并**以退出码 1 结束**；`-h` 是退出码 0。

**3.3.3 失败与重试**

- 失败语义是**整队列**级别的：脚本按文件名顺序处理 `queue/`，处理到第 N 条失败就
  **立即停止、退出码 1**，第 N+1 条及以后完全不碰。此时第 1…N−1 条已发完并移入
  `published/`，**第 N 条原样留在 `queue/`**；修好原因后重跑，只会处理它和它后面的
  （已发布的不会重复发）。
- `--dry-run` 不适用上面这条：它**永远以退出码 0 结束**，单条失败只打印 `❌` 并继续下一条，
  适合一次体检整个队列。
- 常见原因：`缺少 config.json`（先 `cp config.example.json config.json` 并填写）、
  模型输出解析失败（重跑或换更大模型）、账号密码错、网络不通、截图路径不存在。

### 3.4 批量通过：把整批候选一次变成待发清单

复核页（`reports/<source>-<date>.html`）只负责"看"——它只有 *全部 / 仅有图 / 无图* 三个筛选和
复制按钮，**不提供"通过"按钮，也不会回写候选文件**。想一次放行整批候选，就得自己按下面的
口径生成 `queue/<游戏名>.json`（2026-10-04 已对 Steam 那批 8 条做过一次；那次用了一个临时
脚本，脚本本身没入库）：

| 清单字段 | 取值口径 |
|---|---|
| `name` | 候选的 `name` 原样 |
| `panUrl` | 候选的 `url`（Steam 免费游戏就拿商店页当链接，见 `queue/社畜就是要躺平.json`） |
| `panCode` | `"无"` |
| `genre` | 留空——候选数据里没有这个字段，**别编造** |
| `platform` | `"PC"`（Steam 源就是 PC 商店） |
| `tags` | 候选的 `tags` 原样 |
| `notes` | 写清来源 id 与抓取日期，给 AI 一点上下文 |
| `screenshots` | 没图就写 `[]`；**千万别写不存在的路径**，否则正式发布会在发帖前中止 |

两个要注意的点：

1. 文件名用游戏名（`:` 之类特殊字符转成全角，例如 `Demon Lord： Clicker.json`）；**重名的
   不要覆盖**——比如候选第 1 条 `社畜就是要躺平` 早就有手写清单了，跳过它。
2. 生成完先 `node publish-game.mjs --dry-run` 体检（实测约 68 秒/条，8 条约 9 分钟）；
   确认无误再去掉 `--dry-run`。⚠️ `publish-game.mjs` **不带参数时会处理 `queue/` 下全部
   非 `_` 开头的清单**，所以从 1 条变 8 条之后，一次裸跑就是发整队（当前队列 7 条）；想只发一条用
   `node publish-game.mjs --file "queue/<清单名>.json"`（2026-10-04 已用 AutoChart 单条真发
   试过，见 3.5）。

### 3.5 单条真发实录（2026-10-04 首次跑通）

命令（⚠️ 这是真发，会真的发帖）：

```bash
node publish-game.mjs --file queue/AutoChart.json
```

实测输出（原样；`▶` 下面就是全部步骤）：

```text
发现 1 个待发布游戏，开始处理…

▶ AutoChart
  · 本地模型生成文案…完成
  · 进入游戏站…完成
  · 发布帖子…完成（id=3）
  ✅ 已发布：https://kuhai.de5.net/game-post.html?id=3

🎉 全部完成，共发布 1 篇。
```

几件值得记住的事：

1. **整条约 2.5 分钟**（12:36 起跑 → 12:38:36 归档完成），时间几乎全花在本地模型生成文案；
   真发比 `--dry-run` 的 68 秒/条长，整批发布别按 68 秒/条估算。
2. **清单没截图时，「论坛管理员登录 / 上传截图」两步会整段跳过**（分支在
   `publish-game.mjs:324-338`）——输出里看不到这两步是正常的，`forumAdmin` 那对账号只在
   清单带 `screenshots` 时才用得上。
3. **成功后清单会被移走**：`queue/AutoChart.json` → `published/AutoChart.json`，并追加
   `publishedAt` / `postId` / `postUrl`。所以 `queue/` 会少一条，这是设计如此，不是文件丢了；

## 五、如何新增一个 galgame 站点

galgame 是一个**聚合来源**：`sources/galgame/index.mjs` 扫描自己的子目录，逐个动态 import 调用，
失败只跳过该站点、不影响其它站点。新增站点不用改任何公共文件。

```bash
cd /home/zhong/Desktop/project/simple_forum_cf/automation/sources/galgame

# 1. 复制模板
cp -r siteA siteB
```

然后改 `siteB/index.mjs` 四处：

1. `SITE_NAME` —— 保持与目录名一致（`'siteB'`），它决定日志前缀和 `id` 前缀
2. `LIST_URL` —— 目标站点的**列表页**地址；**留空时脚本不发任何请求**，只打印
   "本模板还没配置…本次跳过"，所以配错了也不会误抓
3. `parseList()` —— 按目标列表页 HTML 结构写正则，提取详情页链接
4. `parsePost()` —— 按目标帖子页 HTML 结构写正则，提取标题、正文、图片、链接

验证：

```bash
cd ../..                        # 回到 automation/
node fetch.mjs galgame          # 看日志里 siteB 返回几条
node review.mjs galgame
```

要点：

- 子站点只要导出 `fetchGames()`，抛错会被聚合器接住并标记该站点失败，不影响其它站点；
- 返回的每条数据必须带齐统一格式的必需字段：`id / source / name / desc / url / cover / tags / fetched_at`
  （缺字段会被 `fetch.mjs` 拦下并报错，日志会指出缺哪个）；
- `images` 可以是空数组、`cover` 可以是空字符串 —— 这类"无图"条目会照常入库并打警告；
- 详细字段含义与更多例子见 `sources/galgame/README.md` 和 `sources/galgame/siteA/README.md`。

## 六、代理详解（最容易踩坑的地方）

### 6.1 抓取：fetch.mjs 自己会配代理，不用包脚本

Node 的内置 `fetch` **默认不读 `HTTP_PROXY` 环境变量**，所以脚本里显式打开了
`NODE_USE_ENV_PROXY` 并设好代理。生效优先级：

```
--proxy <url>  >  config.json 的 network.proxy  >  内置默认 http://127.0.0.1:7890
```

因此：

| 你想要的 | 命令 |
|---|---|
| 走本机代理（默认行为） | `node fetch.mjs steam` |
| 换一个代理端口 | `node fetch.mjs steam --proxy http://127.0.0.1:10809` |
| 完全直连 | `node fetch.mjs steam --no-proxy` |
| 长期固定端口 | 在 `config.json` 里加 `"network": { "proxy": "..." }` |

**注意**：脚本刻意**不继承**你在 shell 里 `export` 的 `HTTPS_PROXY`（本机历史上那条
7892 不稳定，实测会 fetch failed）。所以要换代理请用 `--proxy`，不要指望 shell 变量。
（另外记牢：默认一定走代理，任何来源都不例外 —— 不加 `--no-proxy` 就不会是直连。）

### 6.2 run-with-proxy.sh 是给谁用的

它做三件事：加载 `.env` → `export NODE_USE_ENV_PROXY=1` → 加
`--dns-result-order=ipv4first`（避免 IPv6 静默超时）。

`fetch.mjs` 已经自带这套逻辑，所以**抓取不需要它**；真正需要它的是
`publish-game.mjs` 这类"自己不管代理"的脚本 —— 当你要调用云端 API（如 DeepSeek 润色）时：

```bash
./run-with-proxy.sh publish-game.mjs
```

### 6.3 代理失效排查三步

```bash
# 1. 代理本身通不通
curl -s -x http://127.0.0.1:7890 https://www.google.com -o /dev/null -w "%{http_code}\n"   # 期望 200

# 2. 实际用的是哪条线：抓取时第一行必然会打印（list 不发请求，所以不打印）
node fetch.mjs steam        # 看 "🌐 网络：走代理 …" 或 "🌐 网络：直连（--no-proxy）"

# 3. .env / config.json 是否与 Clash 实际端口一致
cat .env
grep -n proxy config.json 2>/dev/null
```

报错信息里如果带 `UND_ERR_CONNECT_TIMEOUT` / `ECONNRESET`，基本就是线路问题：
先 `--no-proxy` 试直连，再 `--proxy` 换口试。

## 七、常见问题

**Q：抓取超时怎么办？**
A：先看报错里的底层错误码。重跑一次通常就好；持续超时按 6.3 排查，或 `--no-proxy` / `--proxy` 换线路。

**Q：复核页图片不显示？**
A：Steam 图床在国内需要代理，浏览器挂系统代理即可；或者直接看 Markdown 版。

**Q：抓到的条目没有封面图，要不要用？**
A：系统**不拦、也不丢**，只打警告（`⚠️` 逐条 + 汇总行"其中无图 M 条"）。用不用由你决定，
HTML 复核页有"仅无图"筛选，专门看这类。

**Q：同一天重复抓取会怎样？**
A：按 `id` 去重后追加，打印"新增 0 条，跳过重复 N 条"是正常现象，不会写重复数据。

**Q：一次抓太多了，想只抓前 N 条？**
A：目前没有 `--limit`。要么改 `sources/steam/index.mjs` 里的筛选逻辑，要么复核时人工挑；
（`--limit` 是待办项，见第十节）。

**Q：`publish-game.mjs` 报"缺少 config.json"？**
A：`cp config.example.json config.json`，然后填 `game.adminUsername/adminPassword`
（发帖必需）等字段。

**Q：没有 `config.json` 时 `--dry-run` 能跑吗？**
A：能。空跑不登录、不发帖，所以缺 `config.json` 只提示一句 ⚠️ 就继续；本地 ollama 的
地址与模型用代码内置默认值（`http://localhost:11434` / `qwen2.5:7b`）。而无参数的正式发布
仍在启动阶段退出，并提示先 `cp config.example.json config.json`。

**Q：发布失败卡住了，会重复发帖吗？**
A：不会。脚本失败即停（退出码 1），失败清单留在 `queue/`，已成功的已移入 `published/`；
修好后重跑只会处理 `queue/` 里剩下的。

**Q：`published/` 里的文件名为什么没有时间戳？**
A：脚本是**原名移动**到 `published/`，再在原 JSON 里追加 `publishedAt` / `postId` / `postUrl`，
要看发布时间看文件内的 `publishedAt`。

**Q：清单文件名为什么要避开 `_` 开头？**
A：`_` 开头的文件会被当作模板**跳过**（`queue/_example-game.json` 就是模板）。
想临时让某个清单不参与发布，把名字前面加 `_` 即可。
例外是 `--file`：显式指定时会照样处理（所以 `_` 模板也能用来空跑体检）。

**Q：`drafts/` 目录是干嘛的？**
A：目前是空目录，当前脚本都不读它。清单统一放 `queue/`。

**Q：想清空某天的抓取结果重抓？**
A：删掉 `candidates/<来源>-<日期>.json`，再跑抓取命令即可。
