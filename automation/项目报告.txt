1. 项目概览
--------------------------------------------------------------------------------
automation/ 是 simple_forum_cf 站点的内容自动化流水线，目标是自动化产出可发布的
候选内容（游戏 / 资源类帖子），把「找游戏 → 复核 → 写文案 → 发帖」从纯手工压成几条命令。

成功标准（本项目的验收口径）：
  1) 抓到的东西字段统一、能一眼复核（HTML 卡片 + 无图筛选）；
  2) 发帖文案由本地模型生成，不花钱；云端润色只在显式配置后才启用；
  3) 任何一步失败都能说清原因、退出码非 0、不产生半成品；
  4) 真发布前必须能空跑体检（--dry-run），且空跑零副作用。

流水线一览（一条链，每一步的产物就是下一步的输入）：

  网络
   → sources/<来源>/index.mjs            各来源自己解析（steam / galgame 子站点）
   → fetch.mjs                           统一字段校验 / 按 id 去重 / 按日期落盘
   → candidates/<来源>-<日期>.json       抓取产物（gitignore）
   → review.mjs → reports/<来源>-<日期>.html + .md    人工复核（无图筛选 / 一键复制 id）
   → queue/<清单名>.json                 人工写 / 批量通过生成：网盘链接 + 截图 + 标签
   → publish-game.mjs                    ollama 生成文案 →（可选）云端润色 →（可选）截图
                                         上传 → 游戏站发帖
   → 游戏站帖子 + published/<清单名>.json  归档（追加 publishedAt / postId / postUrl）

设计原则：
  1) 零依赖：只用 Node 原生能力（fs / path / url / fetch），不引入任何 npm 包；
  2) 一个来源一个目录：sources/<来源名>/index.mjs 导出 fetchGames() 即注册成功；
  3) 统一数据格式：所有来源产出同一套字段，下游发布逻辑只认这一套格式；
  4) 失败隔离：单个站点 / 单条数据出问题只跳过它自己，不拖垮整批；
  5) 可观测：每一步都有中文日志，异常给排查建议。

2.3 数据流向图（文件层面：谁写、谁读、落到哪）
    注：fetch.mjs 内部那 10 个步骤见第 3 节；这里只看文件怎么流动。

  网络（Steam 官方接口 / galgame 站点 HTML）
    │
    ▼
  sources/<来源>/index.mjs        导出 fetchGames(options)，返回统一格式的条目数组
    │  fetchGames()
    ▼
  fetch.mjs                       统一字段守门人校验 → 按 id 去重 → 按日期落盘
    │
    ▼
  candidates/<来源>-<日期>.json   （抓取产物；同一天重跑只会去重追加）
    │  review.mjs（只读 candidates，不修改它）
    ▼
  reports/<来源>-<日期>.html + .md
    │  人用 firefox / VS Code 预览复核：看封面、筛「仅无图」、一键复制 id 与 url
    ▼
  queue/<清单名>.json（手写）+ queue/screenshots/*.jpg（放图）
    │  publish-game.mjs
    │    ├─ ollama     http://localhost:11434   生成 title + 正文（本地，0 元）
    │    ├─ cloudAi     仅当 config.json 配了 cloudAi.apiKey（--dry-run 明确跳过）
    │    ├─ 论坛 KV     仅当清单里有 screenshots（需要 forumAdmin 账号）
    │    └─ 游戏站 API  门禁 → 管理员登录 → 发帖（需要 game.gatePassword / admin*）
    ▼
  游戏站帖子（外部，落地为一个 URL）
    ＋
  published/<清单名>.json         原名移动进来 + 追加 publishedAt / postId / postUrl

  退出码约定：抓取 / 复核出错 → 1（不静默重试）；正式发布处理到第 N 条失败 → 1，且
  后续清单不处理；--dry-run 无论体检结果如何都 → 0。

3. 数据流水线（一次抓取都发生了什么）
--------------------------------------------------------------------------------
命令入口：
  node fetch.mjs <来源名> [--date YYYY-MM-DD] [--proxy <url> | --no-proxy]

执行顺序（括号内为 fetch.mjs 中的行号）：

  1) parseArgs()      解析参数；只允许一个来源；--date 校验 YYYY-MM-DD
  2) loadConfig()     读取 config.json（可选，不存在就用默认值）
  3) applyProxy()     设置 NODE_USE_ENV_PROXY=1 与 HTTP(S)_PROXY（默认 127.0.0.1:7890）
  4) listSources()    扫描 sources/*/ 目录，只有含 index.mjs 的目录才是有效来源   [156]
  5) 动态 import       await import('sources/<来源名>/index.mjs')，调用 fetchGames(options)
  6) validateItems()  统一格式守门人；任何一条不合法 → 打印原因并退出（不写文件）  [185]
  7) 空数据保护       来源返回 0 条 → 提示「本次没有抓到任何数据」，不写文件
  8) mergeById()      与当天已有文件按 id 去重合并（新增 / 跳过重复）             [232]
  9) writeFileSync()  写入 candidates/<来源名>-<日期>.json（JSON，2 空格缩进）
 10) 汇总输出         抓取完成统计行 + 「📊 本次入库 N 条，其中无图 M 条」        [334]

传给来源的 options：{ source, date, automationDir, candidatesDir }
  - date 只影响输出文件名；条目的 fetched_at 始终记录真实抓取时间。


--------------------------------------------------------------------------------
4. 统一数据格式与守门人校验
--------------------------------------------------------------------------------
必需字段（fetch.mjs 第 36 行 REQUIRED_FIELDS，八个字段一个都不能少）：

  id  source  name  desc  url  cover  tags  fetched_at

逐字段规则：

  字段        要求
  --------    --------------------------------------------------------------
  id          非空字符串，且必须以「<来源名>-」开头（例：steam-5076420）
  source      必须严格等于来源名（例：'steam'）
  name        非空字符串
  desc        字符串（可以为空串）
  url         字符串，且是 http(s) 链接
  cover       字符串（没有封面就填空字符串 ''，不允许 undefined）
  tags        数组（没有标签就填 []）
  fetched_at  存在即可（来源自行填「YYYY-MM-DD HH:mm」）
  另：同一批结果内 id 不得重复（重复会直接报错退出）

不在守门人校验范围内的字段：
  images[] / links[] / site  —— galgame 的扩展字段，可选，守门人不管。

校验失败的行为：fail() → 打印「来源「x」第 N 条数据 … 」并终止，不写任何文件，
已有 candidates 文件保持不动。这保证了脏数据永远不会进产物目录。

5. 两个来源的实现
--------------------------------------------------------------------------------
5.1 steam —— 官方接口抓免费游戏（sources/steam/index.mjs，178 行）

  数据源（两个公开接口，无需 key）：
    A. 分类接口 https://store.steampowered.com/api/featuredcategories?cc=CN&l=schinese
       → specials / new_releases / top_sellers 等分类，每类里有 items
    B. 详情接口 https://store.steampowered.com/api/appdetails?appids=<id>&cc=CN&l=schinese
       → short_description（简介）、header_image（封面）、genres（类型标签）

  处理链：
    collectFeaturedItems()  跨分类按 appid 去重
    isFree()                final_price 或 original_price 为 0 即判免费
    SKIP_DEMO = true        详情里 type === 'demo' 的试玩版直接跳过（第 24 行开关）
    逐条请求详情            间隔 REQUEST_INTERVAL = 2000ms（Steam 限流严格）
                            单次超时 REQUEST_TIMEOUT = 20000ms
    容错                    单条详情失败只跳过并计数，不影响整批（唯一允许的容错）
    软警告                  cover 为空 → 计数 + 打印（见第 6 节）

  2026-10-04 实测：分类去重 51 款 → 判免费 14 款 → 跳过 Demo 6 款 → 入库 8 款，
  0 条详情失败，耗时 35.4 秒（14 次详情请求，2 秒间隔）。

5.2 galgame —— 聚合器 + 每站点一个子目录（sources/galgame/index.mjs，215 行）

  架构：sources/galgame/index.mjs 是唯一入口（守门人只 import 它），它在运行时
  扫描自己的子目录，把每个子站点当成一个独立小爬虫来调用。

    sources/galgame/          （磁盘上当前只有：index.mjs、README.md、sites.txt.example、siteA/）
    ├── index.mjs      聚合器
    ├── siteA/         子站点（活模板：LIST_URL 为空 → 打印提示并跳过，不发任何请求）
    ├── siteB/         [计划] 以后照着 siteA 复制；该目录尚未创建
    └── _template/     [约定] 下划线开头 → 被聚合器忽略，可放模板；尚未创建

  子站点约定（每个子目录一个 index.mjs）：
    必须导出  export async function fetchGames(options) { ... }
    返回数组，每条格式：
      { id, source, name, desc, images[], links[], url, fetched_at }
      - id         必须以 galgame- 开头；推荐 galgame-<站点名>-<帖子URL的sha256前12位>
                   （由帖子 URL 派生 → 天然稳定，重复抓取不会产生新 id）
      - source     建议写 'galgame/<站点名>'（聚合器会按下面的兼容层处理）
      - images[]   帖子里的图片地址（无图就 []，不会因此被丢弃）
      - links[]    帖子里出现的所有链接（不判断类型，判断交给人）
      - url        原帖地址

  聚合器做的事（export async function fetchGames，第 135 行）：
    1) listSubSites()   扫描子目录；跳过「.」/「_」开头；没有 index.mjs 的目录视为无效  [68]
    2) 逐个动态 import 子站点的 index.mjs，检查 fetchGames 是否导出
    3) 串行调用（不并发，避免打崩站点），把返回的每条数据交给 normalizeItem()
    4) normalizeItem()  归一 + 单条守门（不是对象 / 缺 id / id 前缀错 / 缺 name /
                        url 非 http(s) → 只丢弃这一条并打印原因）                [89]
    5) 按 id 去重（同一 id 只保留第一条，同时 fetch.mjs 也会拒重复）
    6) 逐条软警告：无图 → 计数 + 打印（见第 6 节）                                [189]
    7) 汇总一行：子站点数 / 成功失败数 / 入库条数 /（丢弃、重复、无图几条）
    8) 返回合并后的数组给 fetch.mjs

  容错矩阵（全部实测过，见第 10 节）：
    情况                        行为
    ------------------------    --------------------------------------------------
    目录里没有 index.mjs        ⚠️ 跳过该站点并打印原因
    子站点 fetchGames 抛异常    ⚠️ 跳过该站点，其它站点照常
    返回值不是数组              ⚠️ 跳过该站点并说明实际类型
    某条数据格式不合法          ⚠️ 只丢弃这一条，其余照常入库
    与其它站点 id 重复          ⚠️ 只保留第一条，计入「跳过重复 id」
    images 为空数组             ✅ 照常入库（仅打印软警告，不丢弃）
    一个子站点都没有            提示「还没有任何子站点」并返回 []（不报错）

  兼容层（sources/galgame/index.mjs 第 36 行 COMPAT_WITH_VALIDATOR = true）：
    守门人要求 source 严格等于 'galgame'、且必须有 cover / tags 字段，而子站点希望
    保留自己的站点标识。兼容模式下的处理：
      source = 'galgame'          （满足守门人）
      site   = 'siteA'            （新增字段，保留「这条是谁抓的」）
      cover  = images[0] || ''    （拿第一张图当封面，没图就是空串）
      tags   = []                 （galgame 帖子本来没有标签）
    子站点代码在两种模式下都不用改；若想落盘时保留 source = 'galgame/siteB'，
    把该开关改成 false，并同时放宽 fetch.mjs 里对应的 4 行校验（README 中有说明）。

  站点模板：sources/galgame/siteA/
    LIST_URL 为空 → 打印「本模板还没配置（LIST_URL 为空），本次跳过」并返回 []，
    不发起任何请求。按同目录 README.md 填上真实站点即可开始抓。

6. 软警告规则（本次新增：无图不丢弃，只提醒）
--------------------------------------------------------------------------------
规则定义：任何来源抓到的条目，如果没有图片，照常入库，只打印一条显眼的警告，
方便人工判断是否需要补齐素材。它是提醒，不是过滤。

判定标准（fetch.mjs 第 226 行 hasNoImage()，统一口径）：
  既没有 images 数组内容、也没有 cover 才算是「无图」：
      const hasImages = Array.isArray(item.images) && item.images.length > 0;
      return !hasImages && !item.cover;
  等价说法：
    - steam：cover === ''（空串 / 缺字段都算没图）
    - galgame：images 为空数组（兼容模式下 cover 也是 ''）
  反过来，只要 cover 有值（哪怕 images 是空数组）就不算无图，不该打扰你复核。

三处实现（全部实测）：

  1) sources/steam/index.mjs 第 159–163 行（逐条警告 + 计数）
       if (!game.cover) {
         noCoverCount += 1;
         console.warn(`[steam]   ⚠️ ${game.name} 无封面图，已入库（建议人工确认）`);
       }
     末行统计同时带上了这个数（第 175 行）：
       [steam] 详情抓取结束：入库 8 款（跳过试玩版 6 款、详情失败 0 款、无封面图 0 款）

  2) sources/galgame/index.mjs 第 188–193 行（放在 merged.push 之后，见下方说明）
       // 软警告：没图也照常入库，只提醒人工确认（不过滤、不丢弃）
       if (unified.images.length === 0) {
         noImageItems += 1;
         console.warn(`[galgame] ⚠️ ${site.name} ${unified.name} 无图，已入库（建议人工确认）`);
       }
     注意位置：刻意放在「已经通过去重、真正 push 进结果」之后，而不是放在
     normalizeItem() 里。因为 normalizeItem() 是纯转换函数，不该掺入「是否入库」的
     业务判断；放在 normalizeItem 里会对「因同 id 被去重丢弃」的条目也打印
     「已入库」，属于误报。实测已验证：两个站点抓到同 id 时，警告只打印一次。
     聚合汇总行（第 207 行）：
       [galgame] 聚合结束：子站点 2 个（成功 2 个，失败 0 个），入库 3 条（跳过重复 id 1 条，无图 2 条，建议人工确认）

  3) fetch.mjs 第 330–334 行（全局汇总，统计口径 = 本次真正新增写入的条目）
       console.log(`📊 本次入库 ${added} 条，其中无图 ${addedItems.filter(hasNoImage).length} 条（建议人工复核）`);
     mergeById() 顺带回传 addedItems（本次真正新增的条目数组），与上一行
     「新增 N 条」完全同口径：
       ✅ 抓取完成：来源返回 3 条，新增 3 条，跳过重复 0 条，文件共 3 条
       📊 本次入库 3 条，其中无图 2 条（建议人工复核）
     重复抓取那天会显示「本次入库 0 条，其中无图 0 条」，与上一行自洽。

约束遵守情况：
  - 不引入任何新依赖（只用 console.warn）；
  - 不改动任何校验 / 过滤逻辑：REQUIRED_FIELDS 与 validateItems() 一个字没动；
  - 落盘数据里允许出现 cover: "" 与 images: []，两者都不是必填项；
  - 来源返回 0 条（没写文件）时不会打印 📊 行。

7. 网络与代理（实测结论）
--------------------------------------------------------------------------------
本机网络情况（实测）：
  - 系统代理：GNOME「手动」设置 → 127.0.0.1:7890
  - shell 环境里的 HTTPS_PROXY（7892）不稳定，实测会 fetch failed，故代码刻意
    不继承 shell 的同名变量（fetch.mjs 第 133–134 行有注释说明）
  - 网络本身间歇性抖动：多次出现 20 秒请求超时（The operation was aborted due to
    timeout）；网络正常时 steam 整批 35.4 秒可跑完

代码里的处理（fetch.mjs 第 128–153 行 applyProxy()）：
  - Node 默认忽略 HTTP(S)_PROXY 环境变量，必须先开 NODE_USE_ENV_PROXY=1
  - 代理优先级：--proxy 参数 > config.json 的 network.proxy > 内置默认值（第 33 行）
  - 默认值：DEFAULT_PROXY = 'http://127.0.0.1:7890'
  - 同时设置 NO_PROXY=localhost,127.0.0.1,::1
  - 直连：--no-proxy（跳过整个代理设置）
  - 来源（sources/）本身完全不用关心网络，代理在调用它们之前就设好了

run-with-proxy.sh：
  - 作用：加载同目录 .env，导出 NODE_USE_ENV_PROXY=1 与
    NODE_OPTIONS="--dns-result-order=ipv4first"（强制 IPv4，避免 IPv6 静默超时），
    然后 exec node "$@"
  - automation/.env 已存在（96 字节，2026-10-04 实测），内容为 HTTP_PROXY / HTTPS_PROXY /
    NO_PROXY，所以运行时不会再打印「⚠️ 未找到 .env 文件」；即使删掉它也能正常抓取，
    因为 fetch.mjs 自己会设默认代理（127.0.0.1:7890）
  - 要用它指定别的代理，直接改 automation/.env：
        HTTP_PROXY=http://127.0.0.1:7890
        HTTPS_PROXY=http://127.0.0.1:7890
        NO_PROXY=localhost,127.0.0.1

12. 附录 A：新增一个 galgame 站点的步骤
--------------------------------------------------------------------------------
  1) 复制模板目录
       cp -r sources/galgame/siteA sources/galgame/siteB

  2) 改文件顶部三个常量（siteA/index.mjs 里都有注释）
       SITE_NAME = 'siteB'          // 站点名，会写进每条数据的 site 字段
       LIST_URL  = 'https://…'      // 站点列表页地址（填上后模板就不再跳过）
       （其余常量：请求间隔、超时、UA 视站点情况微调）

  3) 改两个解析函数
       parseList(html)  → 从列表页解析出「帖子 URL 列表」
       parsePost(html, url) → 从帖子页解析出 { name, desc, images[], links[] }

  4) 遵守 4 条输出规则（聚合器会检查）
       - id 必须以 galgame- 开头，推荐 galgame-<站点名>-<帖子URL的sha256前12位>
         （由帖子 URL 派生 → 天然稳定，重复抓取不会产生新 id）
       - source 写 'galgame/<站点名>'（兼容模式下聚合器会自动归一成 'galgame'
         并把站点名放进 site 字段）
       - name 不能为空；url 必须是 http(s) 链接
       - images 可以是 []（无图不会被丢弃，只会打印软警告）

  自检：
       node --check sources/galgame/siteB/index.mjs
       node fetch.mjs galgame
       # 期望看到：发现 N 个子站点：siteA、siteB …
       #           [galgame] ✅ siteB：返回 X 条，入库 X 条

  注意：目录名以「.」或「_」开头会被聚合器跳过（想放草稿/模板就用 _template/）。

13. 附录 B：常见问题排查
--------------------------------------------------------------------------------
  现象：抓取失败：The operation was aborted due to timeout
     → 网络/代理问题。依次试：重跑；--no-proxy 直连；--proxy <你的代理>；
       确认系统代理端口（本机是 127.0.0.1:7890）。
     → 可用 ./run-with-proxy.sh（依赖 automation/.env，已存在）自动带
       NODE_USE_ENV_PROXY=1 与 ipv4first。

  现象：来源「x」第 N 条数据的 id「y」前缀必须是「x-」
     → id 必须以「来源名-」开头，例如 steam-5076420、galgame-siteA-abc123。

  现象：来源「x」第 N 条数据的 source 必须是「x」
     → source 要与来源目录名严格一致。galgame 的子站点不必自己处理，
       兼容模式会归一；若关掉兼容模式，则需在 fetch.mjs 里放宽这行校验。

  现象：source 目录存在但 node fetch.mjs list 显示「缺少 index.mjs」
     → 该目录里没有 index.mjs，不是有效来源；建了这个文件才注册成功。

  现象：galgame 提示「⚠️ <站点>：目录里没有 index.mjs，已跳过」
     → 子站点目录缺少 index.mjs（或文件名写错）。补齐即可，其它站点不受影响。

  现象：模板目录也被当成站点抓了
     → 把目录名改成下划线开头（如 _template），聚合器会跳过。

  现象：抓取完成「新增 0 条，跳过重复 N 条」
     → 正常：同一天重复抓取时，id 已存在所以不重复写入。id 由帖子 URL 派生，
       稳定不漂移，这正是想要的行为。
     → 想重新生成这一天的文件，先备份/删除 candidates/<来源>-<日期>.json 再抓。

  现象：candidates 里出现了 cover 为 "" 或 images 为 [] 的条目
     → 这是允许的（软警告规则：无图不丢弃）。日志里会有对应的 ⚠️ 提醒与
       「📊 本次入库 N 条，其中无图 M 条（建议人工复核）」统计，交给人工判断。

14. 成本与 API
--------------------------------------------------------------------------------
当前（2026-10-04 实测）：
  · 抓取层：零 API 成本。steam 走官方公开接口，galgame 走站点页面解析，
    全程不需要 API Key，也不产生任何费用。
  · 发布层文案：本地 ollama 生成（默认 http://localhost:11434，模型 qwen2.5:7b），
    实测一条约 280 字中文文案，只花显卡电费。--dry-run 也是走本地模型，
    不会因为"空跑练手"产生任何外部调用。
  · 唯一可能产生费用的开关是 config.json 里的 cloudAi：只有配了它，
    publish-game.mjs 才会去调云端润色；--dry-run 明确跳过这一步。

未来若接入 DeepSeek（或同类云端模型）做润色/校对，建议的控费策略：
  1) 默认关闭：cloudAi 留空即不调用，本地稿够用就不打开；
  2) 只润色不生成：把本地初稿（几百字）交给云端改写，输入小、输出可控；
  3) 每条清单只调一次云端（不做失败重试风暴），失败就退回本地文案照发；
  4) 先空跑估量：新题材先用 --dry-run 看本地稿质量，确认值得润色再正式发；
  5) 留痕可核对：每次真发布的结果记进 published/*.json，方便按条对账；
  6) 预算红线：给单条 token 上限与月度额度，超限直接退回本地文案，不静默重试。

一句话：现在跑一天的抓取 + 发布，成本是 0 元；费用只会出现在你主动打开 cloudAi 之后。
