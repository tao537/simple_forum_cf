# Agent 成本优化报告

> 面向：项目所有者（人）
> 主题：**如何降低 AI Agent 在本项目上的 token 消耗**
> 日期：2026-10-05
> 位置：`simple_forum_cf/docs/Agent优化报告.md`

---

## 一、结论（先看这段）

问题的根因不是「AI 读得太多」，而是**每次会话都要从零摸索这个项目**。

解决办法是**给 Agent 一份自动注入的项目地图**，让它开口就知道一切。
本报告记录已做的优化、背后的机制、以及**比改文件更重要的使用习惯**。

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 每次会话的「认清项目」成本 | 约 **247 KB ≈ 6.2 万 tokens**（要翻日记、README、交接指南、项目报告、后端的 1869 行…） | **10.7 KB ≈ 2.7 千 tokens**（自动注入，零工具调用） |
| 差距 | — | **约 24 倍** |

---

## 二、成本到底花在哪

一次会话的开销由三部分组成：

1. **固定开销**：系统提示 + 工具定义（无法优化）
2. **认清项目**：读文件、列目录、grep —— **这是本项目的主要浪费**
3. **干活本身**：真正修改代码、验证 —— 这部分该花

第 2 项之所以贵，是因为项目里有一批**大体量文档**：

| 文件 | 体积 | 说明 |
|---|---|---|
| `automation/项目报告.txt` | 69 KB | 技术全貌，947 行 |
| `automation/使用教程.md` | 31 KB | 手把手教程 |
| `automation/交接指南.md` | 28 KB | **已过期**，会误导 |
| `注意` | 19 KB | 2026-10-01 迁移日记 |
| `README.md` | 12 KB | 部署说明 |
| `backend/src/index.ts` | 75 KB | 全部后端代码，1869 行 |

Agent 为了让回答准确，会倾向于**把这些都读一遍**。这是最贵的路径。

---

## 三、已做的三项改动

### 1. 新增 `AGENTS.md`（核心）

放在**工作目录根**（`<工作目录>/AGENTS.md`），由 DSH 在**每次会话第一次请求时自动注入**，
不需要 Agent 主动读取、不产生任何工具调用。

内容是「地图」而非「文档」：

- 项目是什么、架构一句话、仓库根在哪（**本工作目录不是 git 根**，这个坑很费时间）
- 目录地图，**每个文件标注规模**——用来判断「值不值得读」
- 后端 71 个路由的**行号锚点**（改接口时直接跳过去，不用通读 1869 行）
- 前端导出函数行号
- automation 流水线的关键约定
- **9 条踩过的坑**（XSS 要先转义、D1 是 SQLite、KV 返回绝对地址、Pages 会把 `.html` 308 跳转、密钥别打印、禁止软链接…）
- 常见任务速查表
- **「按需查阅」表**：明确点名哪些大文件**默认不要读**，以及真要读时该怎么读

### 2. 删掉纯重复的 `部署说明.md`

它和 `README.md` **逐字节完全相同**（都是 12,487 B）。删掉后仓库只剩一份，避免 Agent
「读了一个又发现另一个」而把内容读两遍。

### 3. 给过期的 `交接指南.md` 加「历史存档」警示头

这份 28 KB 的文档写于 2026-10-04，之后项目多次变更，**里面的信息已经错了**：

| 文中说 | 实际 |
|---|---|
| 工作目录 `/home/zhong/Desktop/project/...` | `/home/zhong/Disk_R/DesktopProject/project/...` |
| 领先 origin/main 2 个未 push 提交 | 早已同步 |
| `published/` 8 条 | 已更多 |
| 缺提取码只留本地警告 | 现在还会在正文插入说明 |

一个 Agent 读了它，会**按错的信息行动**，比不读更糟。现在文件顶部有醒目的过期警示 + 正确做法。

## 四、机制：DSH 是怎么加载 `AGENTS.md` 的

（这部分是从插件 `@deepseek-ai/dsh-agent-instructions` 的源码和文档里核实出来的，不是猜的）

### 加载哪些文件

| 位置 | 是否加载 |
|---|---|
| `$DSH_HOME/AGENTS.md`（即 `~/.dsh/AGENTS.md`） | ✅ **全局**，对所有项目生效 |
| `<项目根>` → `<工作目录>` 链上每一层的 `AGENTS.md` / `CLAUDE.md` | ✅ |
| 同目录的 `AGENTS.local.md` / `CLAUDE.local.md` | ✅ 叠加 |
| **其他目录下的 `AGENTS.md`** | ❌ 但会在 Agent 读写到那个目录后被**追加**进来 |

- **项目根怎么定**：从工作目录往上找 `.git`。**找不到就认定「工作目录自己就是项目根」。**
- 内容完全相同的同级文件只渲染一次（例如 `CLAUDE.md` 是 `AGENTS.md` 的副本）。
- **预算 65536 字节**；超了会先丢弃较宽泛的文件，最后才截断最具体的那份。

### ⚠️ 一个重要陷阱（本次实测踩到）

我们一开始把 `AGENTS.md` **同时**放在工作目录和仓库里（`simple_forum_cf/AGENTS.md`）。

结果：会话第一条消息里出现了 **两份**（`Instructions from: AGENTS.md` +
`Additional instructions from: simple_forum_cf/AGENTS.md`）——因为仓库自己有 `.git`，
所以它是一个**独立的项目根**，Agent 一旦读写它下面的文件，这份就会被追加进来。

**成本直接翻倍。** 已修正：仓库备份改名为 `docs/项目速览.md`（√ 不是候选文件名，不会被注入）。

> **自查方法**：看会话开头 system-reminder 里有几条 `Instructions from`。多于一条就是在重复计费。

### 为什么备份不叫 `AGENTS.md`

项目**禁止软链接**（所有者要求，已写进 `AGENTS.md` 第 9 条约定），所以用**真实副本**。
但副本不能叫 `AGENTS.md`，否则如上所述会被重复注入。

最终结构：

```
<工作目录>/AGENTS.md                    ← 自动注入（唯一真相，改这份）
simple_forum_cf/docs/项目速览.md        ← 仓库备份（不自动加载，随 git 走）
```

⚠️ **改内容必须同步两份**（改①，再复制到②）。

## 五、比改文件更重要的：使用习惯

工具改好了，但**最大的杠杆在使用方式上**。

### 1. 一个任务一个会话（最重要）

**长会话的每一轮，都会把之前所有的文件内容重新发一遍。**

这意味着：一个拖了 50 轮的会话，每轮都在为前 49 轮读过的 `index.ts` 付费。

以前不敢开新会话，是因为「开场要重新摸索，很贵」；**现在开场只要约 2.7 千 tokens**。
所以：

> **做完一件事就结束会话。下一件事开新会话。**

### 2. 让它「先定位，再读那一段」

不要问「这个项目怎么实现的」，而要问「`IMG_RE` 定义在哪、它对图片 URL 有什么要求」。
前者会让它通读，后者只需一次 grep + 一次定点读取。

`AGENTS.md` 里已经写了这条纪律，但你直接下指令效果更好：

> 「**用 grep 定位，只读相关那几十行，不要通读文件。**」

### 3. 点名禁止读大文件

需要「为什么这么设计」时才去碰 `注意` / `项目报告.txt`。日常改动完全不需要。
直接说：**「不要读 `项目报告.txt` 和 `注意`。」**

### 4. 限制命令输出

`cat` 一个大文件 = 把整个文件塞进上下文。用 `head` / `tail` / `grep -n` / `wc -l` 代替。

### 5. 用「可运行的验证」代替「读代码理解」

本项目已经有很多现成的验证手段：`node --check`、`--dry-run`、`curl` 线上接口、D1 查询。
让 Agent「跑一遍看结果」，比让它「读 700 行脚本推理」便宜得多，也更准。

### 6. 明确边界，减少来回

一句「**只改 X，不要动其他文件**」，能省掉大量「要不要顺便…」的试探和回滚。

## 六、维护规则

`AGENTS.md` 一旦过期，就会从「省钱工具」变成**误导源**。所以在这些时刻要更新它：

- 新增/删除/重命名重要文件
- 改了架构（换存储、换框架、拆分文件）
- 新增一条「踩过的坑」
- 行号锚点漂移得厉害时（不必精确，定位用）

**判断标准**：如果下一次会话的 Agent 会因为这份文件里的信息做出错误决定，就必须更新。

目标体积：**控制在 20 KB 以内**（当前约 10.7 KB，占 DSH 预算 16%）。

## 七、还可以进一步做的（可选）

| 想法 | 收益 | 代价 |
|---|---|---|
| 把「大文档」挪进 `docs/archive/` 并加过期头 | 降低被误读的概率 | 需要人工搬运 |
| 把 `项目报告.txt`(69 KB) 拆成几篇小文档 | 可按需单读 | 工作量大 |
| 在 `~/.dsh/AGENTS.md` 写**跨项目**偏好（如「永远先 grep 再读」） | 所有项目受益 | 与项目文件可能冲突，要小心 |
| 后端 `index.ts`(1869 行) 按模块拆分 | 定点读取更省 | 有回归风险，需充分测试 |
| `自动化 review → 选择 → 入队`（之前讨论的 B 方案） | 减少人工来回 | 见 `交接指南.md` 历史讨论 |

DSH 相关（已核实）：

- 插件：`@deepseek-ai/dsh-agent-instructions`，`dsh-base` **默认启用**，你的 profile 未禁用
- 预算：`maxBytes = 65536`
- 候选文件名：`AGENTS.md`、`CLAUDE.md`（+ `AGENTS.local.md`、`CLAUDE.local.md`）
- 项目根标记：`.git`
- 注入时机：**首次请求**即注入基线；之后读写到更深目录会追加新的指令文件
