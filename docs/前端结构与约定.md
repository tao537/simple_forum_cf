# 前端结构与约定

> 前端是纯静态文件，由 Cloudflare Pages 直接从 `frontend/` 发布，没有构建步骤。
> 所以「模块化」在这里的含义是：**共享内核 + 页面级文件 + 页面自己的 css/js**，
> 每个文件都能单独改、单独缓存、单独 diff，不靠打包工具。

## 一、目录与文件

```
frontend/
├── common.js          # 前端内核：登录态、请求封装、导航、Toast、显示设置（871 行）
├── admin.html         # 后台页 markup（362 行）
├── admin.css          # 后台页样式（162 行，2026-11 从 admin.html 抽出）
├── admin.js           # 后台页逻辑（597 行，2026-11 从 admin.html 抽出）
├── forum.html / post.html / user.html / notifications.html / login.html
├── game.html / game-post.html
├── index.html / music.html / novel.html / video.html / tools.html / 404.html
├── _headers           # 安全响应头 + 缓存规则
└── music/ uploads/ vendor/ wallpapers/   # 静态素材
```

`common.js` 是唯一被所有页面 import 的文件，版本号写在 import 语句里：

```js
import { auth, api, ... } from './common.js?v=20261027';
```

## 二、分层判据

- `music-playlists.js`（音乐板块的补充）：单独管「歌单数据 + 侧栏界面」，页面只通过 `mountPlaylistPanel` / `Playlists` 调它，
  它不反向依赖页面。播放引擎仍留在 `music.html` 的内联 module 里——那部分和本页 DOM 强绑，抽走没有收益。

| 放哪 | 判据 |
|---|---|
| `common.js` | 所有页面都要用、且与具体页面无关（登录态、请求、导航、Toast、显示设置） |
| `xxx.html` | 只有结构：DOM + 少量必须内联的属性 |
| `xxx.css` | 页面专属样式；跨页面共用的视觉规则才考虑提到 `common.js` 旁的共享 css |
| `xxx.js` | 页面专属逻辑，`window.xxx` 挂出去给 HTML 的 `onclick` 用 |

后端接口永远放在对应的 `backend/src/modules/*`，前端不认识「模块」，只认识 URL。
一条功能的改动因此是「前端一个文件 + 后端一个模块」，两边不交叉。

## 三、后台页的三件套（本次改动）

原来 `admin.html` 是 999 行的单文件（124 行内联 `<style>` + 537 行内联 `<script type="module">`），
现在拆成：

| 文件 | 内容 | 行数 |
|---|---|---|
| `admin.html` | 导航、11 个标签按钮、11 个 `panel-*` 面板 | 385 |
| `admin.css` | 卡片、统计卡、表格、按钮、筛选栏、体检项、窄屏适配 | 162 |
| `admin.js` | `window.xxx` 处理函数 + 每页 loader + 启动逻辑 | 597 |

拆分是纯搬移，**行为不变**：HTML 里的 `onclick="switchTab('posts')"` 仍然走 `window.switchTab`，
所以把逻辑搬到外部文件后不需要改任何一处调用。

顺带做了三件用户体验上的小事（都在 `admin.css` / `admin.js` 里）：

1. **标签页记忆**：切到「用户管理」后刷新，回来还是「用户管理」（`localStorage.admin_last_tab`）。
2. **深链**：地址栏同步 `#tab`，`/admin#gate` 能直接打开门禁页；`#hash` 优先于记忆值。
3. **窄屏适配**：≤820px 时表格横向滚动而不撑破版心、标签栏吸顶、切页淡入（尊重 `prefers-reduced-motion`）。

## 四、缓存与版本号（踩过的坑）

Pages 对静态 JS 的 `Cache-Control` 会忽略 `_headers` 里的设置，浏览器可能缓存数小时；
曾经因为 `common.js` 的旧缓存继续调用不可达的域名，表现为门禁「请求超时」。所以约定：

- 改 `common.js` → 所有 HTML 里的 `?v=2026xxxx` 一起加一；
- 改 `admin.js` / `admin.css` → `admin.html` 里这两处 `?v=` 一起加一；
- `_headers` 里也给 `/admin.js`、`/admin.css` 补了 `max-age=0, must-revalidate`（当保险，不当主力）。

## 五、新增一个后台控件要动哪几处

1. 后端：在对应 `modules/*.ts` 加路由（若不是新域，别新建模块）；
2. `admin.html`：在对应 `panel-*` 里加控件，`onclick` 指向 `window.xxx`；
3. `admin.js`：实现 `window.xxx`，需要新数据就在该面板的 loader 里拉；
4. 需要新样式才动 `admin.css`，能复用 `.card/.btn/.filter-bar` 就别新造；
5. 改完 `?v=` 加一。

## 六、验证方式（没有 wrangler、没有浏览器自动化的条件下）

- `admin.js` 这类整块脚本：抽出来直接 `node --check`（ES module 语法检查）；
- HTML 与 JS 的契约：用脚本核对 `data-tab` 与 `id="panel-*"` 是否一一对应、
  `onclick` 引用的 `window.xxx` 是否真的定义了；
- 发布后实测：`https://kuhai.de5.net/admin` 必须**不带 `.html`**（Pages 会 308 去掉后缀），
  再确认 `/admin.css`、`/admin.js` 都能 200。

- 公共视觉变量（主色、圆角、阴影）目前散在各页，将来可以抽一份 `theme.css` 做设计令牌，
  但需要逐页回归，不宜和后端改造混在一次改动里。
