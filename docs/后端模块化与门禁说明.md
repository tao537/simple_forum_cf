# 后端模块化与门禁说明

> 把单文件 `backend/src/index.ts`（2155 行）按职责拆成「共享内核 + 领域模块」，
> 入口已裁剪到 **632 行**（只留装配、认证、用户/通知/统计等剩余路由）；游戏站门禁独立成可单独演进、
> 可单独测试的模块，管理后台新增「🔐 门禁」页。

## 一、目录结构

```
backend/src/
├── index.ts           # 装配入口：CORS + 挂载模块 + 认证/用户/统计等剩余路由（632 行）
├── types.ts           # 全局类型（Bindings / Env / AuthPayload / SessionUser）
├── lib/               # 共享内核：无业务语义，可被任何模块复用
│   ├── security.ts    # 图片白名单、口令策略、PBKDF2 哈希与校验
│   ├── auth.ts        # 统一账号登录态：签发/解析 token、实时封禁、管理员判定
│   ├── settings.ts    # site_settings 单行 JSON 的读 / 写 / 局部改
│   └── notify.ts      # 通知落库 + @提及解析（帖子/评论共用）
└── modules/           # 领域模块：各自闭环，互不 import
    ├── gate.ts        # 门禁（访问控制）：开关 / 密码 / 有效期 / 提示词 / 踢出
    ├── posts.ts       # 论坛帖子与评论：列表、详情、发帖、点赞、编辑删除、置顶精选、批量操作
    ├── game-posts.ts  # 游戏站帖子与评论
    ├── site.ts        # 站点配置：界面显示设置、分类、文案（banner/公告/页脚）
    └── media.ts       # 媒体代理：音乐试听、小说、影视
```

依赖方向是单向的：

```
modules/*  →  lib/*  →  types.ts
index.ts   →  modules/* , lib/*
```

判断一个东西该放哪：

- 只有某一条业务线用 → 放进对应 `modules/`；
- 多条业务线都要用、且没有业务语义 → 放进 `lib/`；
- 只是把模块接起来 → 留在 `index.ts`，不要在入口里塞实现。

## 二、门禁模块（modules/gate.ts）

### 职责边界

只管「能不能进站」：进站密码、通行证签发与校验、门禁开关与有效期、提示词、强制踢出。
**不负责账号注册/登录**——那是 `lib/auth.ts` 的统一登录态（论坛与游戏站共用一套 token）。

对外只暴露四个符号：

| 导出 | 用途 |
| --- | --- |
| `default`（Hono 子应用） | 门禁相关路由，由 `index.ts` 用 `app.route('/', gateRoutes)` 挂载 |
| `requireGate(c)` | 受保护接口的门禁校验，通过返回 `{ ok: true }`，否则 `null`；门禁关闭时直接放行 |
| `loadGate(db)` | 读取完整门禁配置（含旧数据兼容） |
| `saveGate(db, cfg)` | 写回门禁配置（并清理旧字段） |

### 数据模型

配置存在已有的 `site_settings.data.gate` 里，**不需要任何数据库迁移**：

```json
{
  "gate": {
    "enabled": true,            // 关闭后无需密码即可进站
    "passwordHash": "pbkdf2$...",// 空字符串表示尚未设置
    "hint": "密码框上方的提示词",
    "ttl": 43200,               // 通行证有效期（秒），1 小时 ~ 30 天
    "version": 1                // 门禁版本，改密码 / 踢出时 +1
  }
}
```

历史字段 `data.gamePasswordHash`、`data.gamePasswordHint` 会在首次读取时自动识别，
下一次写入时被迁移进 `gate` 并删除，旧前端/旧接口不会因此报错。

### 通行证机制

- 请求头 `X-Gate-Token: Bearer <jwt>`，payload 为 `{ scope: 'game', ver, iat, exp }`；
- `scope` 必须是 `game`；`ver` 必须等于当前门禁版本；`exp` 由 `ttl` 决定；
- **改密码或强制踢出会让版本 +1**，此前签发的所有通行证在下一次请求时立即失效；
- 门禁关闭时 `requireGate` 直接放行，前端也不再弹密码框。

### 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/game/gate` | 公开 | 门禁状态：`{ enabled, hasPassword, hint, ttl }` |
| GET | `/api/game/hint` | 公开 | 兼容旧接口，只返回提示词 |
| POST | `/api/game/enter` | 公开 | 校验访问密码 → 签发通行证 |
| GET | `/api/game/me` | 需通行证 | 通行证有效性 + 当前登录账号 |
| GET | `/api/admin/gate` | 论坛管理员 | 读取配置（不含哈希） |
| PUT | `/api/admin/gate` | 论坛管理员 | 局部更新 `enabled / ttl / hint / password` |
| POST | `/api/admin/gate/kick` | 论坛管理员 | 版本 +1，踢出所有已进站会话 |
| PUT | `/api/admin/game/password` | 论坛管理员 | 兼容旧接口（等价于 PUT `/api/admin/gate` 传 password） |
| PUT | `/api/admin/game/hint` | 论坛管理员 | 兼容旧接口 |

## 三、游戏帖子域（modules/game-posts.ts）

原先散在入口里的 20 个游戏站读写接口整体迁入本模块（391 行）：

- 列表 / 精选 / 搜索联想 / 详情 / 发帖 / 点赞 / 评论 / 评论点赞 / 编辑 / 删除 / 置顶 / 精选切换；
- 所有接口统一先过 `requireGate`，门禁不通过一律 401（模块内封装成 `gateDenied(c)`，避免每个路由重复三行）；
- 作者判定与管理员判定收敛为两个内部函数 `canAuthorOrManage` / `requireManager`，
  原作者逻辑（访客标识或统一账号 = 作者；任一管理员 = 可管理）不变；
- 路由注册顺序依旧是「`/featured`、`/suggest` 在 `/posts/:id` 之前」，否则会被当成 id 吞掉。

## 四、站点配置域（modules/site.ts）

- `/api/settings`（读/改界面显示设置）、`/api/admin/categories`、`/api/admin/site-content`、`/api/site-content` 全部迁入；
- 三类配置（显示设置 / 分类 / 文案）共用同一个读入口 `getSiteSettings`，写回整行 JSON，
  避免早先各路由分别手写 SQL 时互相覆盖；
- 只导出模块路由与常量，入口不再直接碰 `site_settings`。

## 五、管理后台「🔐 门禁」页

`frontend/admin.html` 新增标签页，控件包括：

1. **状态卡片**：门禁开关、密码是否已设置、通行有效期、门禁版本；
2. **开关与有效期**：开启（需密码）/ 关闭（自由进入）；1 小时 / 6 小时 / 12 小时 / 1 天 / 7 天 / 30 天；
3. **访问密码**：4-50 位，保存后立即踢掉所有已进站用户（版本 +1）；
4. **门禁提示词**：显示在游戏站密码框上方，200 字以内；
5. **强制踢出**：一键让所有通行证失效，用户需重新输入密码。

游戏站页里原来的「修改密码 / 提示词」两张卡片已收敛为跳转入口，避免同一配置存在两处入口。

`frontend/game.html` 进站流程也做了适配：先请求 `/api/game/gate`，门禁关闭时直接进站、不弹密码框。

## 六、本轮验证

- 全部 `.ts` 文件通过 `tsc --strict`（仅剩原有的 4 处 `c: any` 泛型调用提示 + 1 处历史隐式 any，属既有写法）；
- 门禁模块 50 项集成测试全过；组装后整体冒烟 **32 项全过**（内存 D1 + 真实 Hono 路由），
  覆盖游戏帖子域挂载、论坛帖子域挂载（发帖鉴权 / `/featured` 与 `/suggest` 未被 `/:id` 抢占 / 批量操作鉴权）、
  路由顺序、鉴权状态码、临时后门已消失、公开设置不泄露哈希；
- `admin.html`、`game.html` 的内联脚本通过语法检查；
- 未新增数据库迁移脚本，无需改动 D1 schema。

## 七、本轮顺带清理

- 删除 `POST /api/game/reset-admin-password`（无鉴权的临时接口，会把站长账号密码硬重置为固定口令）。
  现在改密码只能走管理后台或需要管理员身份的门禁改密接口。
- 入口里不再保留 `VISITOR_RE`、`getSettings`、`readSettings/writeSettings` 等已迁走的实现。
- **修复公开设置接口泄露密码哈希**：`GET /api/settings` 过去把 `site_settings.data` 整包返回，
  连带把 `gamePasswordHash`（迁移后为 `gate.passwordHash`）发给了任何访客。
  现在该接口只回显示相关 5 个字段（`cardSize / density / imageMaxWidth / imageQuality / thumbnailSize`），
  管理端 `PUT /api/settings` 的响应同样只回这 5 个字段。

> 教训：`site_settings` 是一行 JSON，多个域共用一个存储位，凡是「整包返回」的地方都等于把别人的
> 敏感字段一起发出去。新加配置时请同时检查所有读这一行的接口，默认走白名单而不是整包透传。

## 八、部署

- **前端**：`git push` 后 Cloudflare Pages 自动构建；
- **后端**：在 Linux 机器上 `cd backend && npx wrangler deploy`（Windows 上 `node_modules` 是 Linux 版，无法直接跑 wrangler）；
- 首次进站时如果门禁配置还是旧的，会在写回时自动迁移为 `gate` 结构，无需人工介入。

## 十、安全口径统一（本轮顺手修的四点）

1. **口令策略不再有第二个口子**：`POST /api/game/register` 原来只要求 6 位、且不查弱口令黑名单，
   与论坛 `validateCredentials`（8 位 + 黑名单）不一致，而两者写的是同一张 `users` 表。
   现已统一为 8 位 + `BAD_PASSWORDS` 拦截。
2. **CSV 导出加 UTF-8 BOM**：`/api/admin/export/*` 原来无 BOM，Excel 直接双击打开中文全乱码；
   同时给 `=` `+` `-` `@` 开头的单元格前置单引号，阻断公式注入。
3. **最后一道管理员防线**：`PATCH /api/users/:id/role` 允许把管理员降级为用户，若降的是最后一个管理员，
   后台会彻底失联。现加校验：降级后管理员数不能为 0，否则 400「至少需要保留一个管理员」。
4. **`/api/auth/me` 改为以库为准**：原来直接回 token 里的 payload，角色被提升/降级后要重新登录才生效；
   现在每次查库返回 id/username/nickname/role。另外 `issueToken(c, user)` 改为显式传三字段，避免把整行（含 `password_hash`）喂给签发函数。

## 十一、后续可继续按同一模式拆的边界

`index.ts`（632 行）里仍留有：认证（注册/登录/改密）、用户管理（含封禁/搜索/个人主页）、
通知、管理统计、游戏站管理增强、数据导出。

已完成：`lib/notify.ts`（通知落库 + @提及解析）、`modules/posts.ts`（论坛帖子 + 评论 + 批量操作，17 条路由）。

建议顺序：`modules/users.ts`（用户管理 + 封禁 + 个人主页）→ `modules/notifications.ts` →
`modules/admin.ts`（统计 + 游戏站管理增强 + CSV 导出）→ `modules/auth.ts`（注册/登录/改密，最后动，牵涉面最广）。
拆分方式与本轮一致：模块自带 `Hono` 子应用、只依赖 `lib/`，在 `index.ts` 里 `app.route('/', …)` 挂载。
搬迁时保持注册顺序：`/featured`、`/suggest`、`/batch` 要在 `/api/posts/:id` 之前，否则会被当 id 吞掉。

## 十二、后台控件补齐（本轮：接口 ↔ 界面逐项对照）

后台原有 9 个面板（概览 / 帖子 / 用户 / 分类 / 游戏站 / 门禁 / 文案 / 界面设置 / 导出），
本轮按「后端有接口但界面没入口」补了四处：

1. **门禁默认口令红条**：`GET /api/admin/gate` 新增 `usingDefaultPassword` 字段——管理端对当前哈希做一次
   PBKDF2 校验，确认是否仍等于出厂默认口令（只在管理接口算，公开接口不碰哈希）。
   命中时后台「🔐 门禁」页顶部显示红色风险卡，「访问密码」四宫格显示「默认口令 · 不安全，请更换」。
   改密保存后门禁版本 +1、红条自动消失。
2. **用户管理筛选**：新增「全部 / 仅管理员 / 仅已封禁 / 仅正常」下拉，并显示筛选后计数；
   用户名改为链接到 `/user.html?id=…` 个人主页，方便从后台直接核对某人内容。
3. **游戏帖改图**：`PUT /api/admin/game/posts/:id/images` 之前没有入口，现在每行加「改图」按钮，
   弹框输入逗号分隔的图片地址，前端按同一套白名单正则（`/img/…` 或 `https://api.kuhai.de5.net/img/…`，≤9 张）先校验再提交。
4. **导出页文案**：注明导出文件已带 UTF-8 BOM，Excel/WPS 双击不乱码。

验证：后端 `tsc` 仍是 5 条历史遗留诊断、门禁 50 项 + 冒烟 32 项全过；`admin.html` 内联 `<script type="module">`
抽出后 `node --check` 通过。
