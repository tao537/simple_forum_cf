# 界面优化与后续模块规划

> 这份文件记的是一份**已定下的决定**，不是选项清单。原则一句话：
> **后端继续一个能力一个模块；前端不引构建工具，用 CSS 变量收敛而不是重写。**

## 一、现状判断（先看清再决定）

| 项 | 现状 | 结论 |
|---|---|---|
| 前端形态 | 10 个静态 HTML + 原生 ES module，无构建 | 保持。引框架会把「改一行 push 就上线」变成要装环境、要打包 |
| 样式 | `common.js` 共享逻辑，但每页的样式各写各的（admin 有独立 `admin.css`，其余页内联） | 收敛方向：抽公共样式变量，不追求全站统一重写 |
| 后台 | `admin.html` + `admin.js` + `admin.css` 三件套，10 个标签页（含本轮新增「站点体检」） | 结构是好的，继续按「一个标签页 = 一个能力」加 |
| 后端 | 9 个领域模块 + 4 个 lib，`index.ts` 44 行纯装配 | 新能力一律新建模块，不再往入口里加路由 |

## 二、已经做了的（P0，本轮交付）

**「🩺 站点体检」标签页 + `modules/health.ts`**

把原先要靠外部脚本一条条 `curl` 才能确认的状态收成一页只读检查：

1. 站点配置里有没有密码哈希等敏感键（对应那次 `/api/settings` 泄露事故）
2. 门禁开关是否开启
3. 门禁口令是否还是出厂默认（服务端真做一次 PBKDF2 比对，只回结论不回哈希）
4. 管理员账号数是否为 0
5. 管理员是否还在用历史默认密码
6. 内容数据质量：未分类帖子 / 无封面游戏帖
7. 今日活跃与数据规模

验收：`GET /api/admin/health` 未登录 401；返回 `items[]` 每项带 `level: ok|warn|bad` 与一句人话。

## 三、P1 — 前端样式收敛（下一步优先做这个）

**问题**：同一套按钮/卡片/空态在 10 个页面里各写一份，改一处要动十处；颜色靠手抄 `#3b82f6`。

**做法（不自上而下重写）**：

1. 新建 `frontend/theme.css`，只放三样东西：
   - CSS 变量：主色 / 文字三级 / 圆角 / 阴影 / 间距（与现有取值完全一致，先保证「换了等于没换」）
   - 组件类：`.card` `.btn` `.btn-ghost` `.btn-danger` `.empty` `.tag`
   - 移动端断点变量
2. 迁移顺序：`admin`（已有 `admin.css`，先把它的字面量换成变量）→ `notifications` → `user` → `login` → `forum` / `game` 列表页 → 详情页最后。
3. 每迁一页，必须同步把该页 `?v=` 版本号 +1（手机缓存只认版本号）。
4. 验收标准：迁完的页面在 375px 与 1280px 下视觉与迁移前一致；`node --check` 过；控制台无报错。

**不做**：不改交互流程、不引入图标库、不改配色（换视觉是另一件事，等有明确想法再说）。

## 四、P2 — 举报与审核队列（第一个真正新增的功能模块）

社区站没有这条线，出问题只能靠管理员翻帖子。落点：

- 新表 `reports`：`id / target_type(post|comment|game_post|game_comment) / target_id / reporter_id / reason / status(pending|rejected|handled) / handled_by / created_at / handled_at`
- 新模块 `backend/src/modules/reports.ts`：
  - `POST /api/reports`（登录用户，一天内同一对象只能报一次）
  - `GET /api/reports/mine`（我报过的）
  - `GET /api/admin/reports?status=`、`POST /api/admin/reports/:id/handle`、`POST /api/admin/reports/:id/reject`
- 前端：帖子详情页加「举报」小按钮（弹 `prompt` 选原因，不引入弹窗组件）；后台加「🚩 举报处理」标签页，列表 + 一键跳到原帖 + 处理/驳回。
- 边界：本模块不删帖、不封人。处理动作只改 `reports.status`，真正处置交给人去对应模块操作——避免一个按钮同时改两张表。

## 五、P3 — 内容侧的两个小模块（按需再做）

| 模块 | 为什么值得 | 成本 |
|---|---|---|
| 草稿箱 `modules/drafts.ts` + `drafts` 表 | 长帖写着写着丢了是真实痛点；后台可看未发布草稿 | 小 |
| 标签 `modules/tags.ts` | 分类只有一层，找老帖效率低；`tags` 表 + 帖子 JSON 里的 tag 数组即可，不必上关联表 | 小 |

**暂不做**：站内搜索改 FTS5（现有 `LIKE` 在这个体量够用，换 FTS 要动迁移和排序，收益不明显）；评论嵌套树；私信；R2 迁移。

## 六、执行纪律（每次都照这个走）

1. 改后端 → 新模块 + 在 `index.ts` 加一行挂载；`tsc` 诊断条数不许增加；补冒烟断言。
2. 改前端 → 同步 `?v=`；`node --check`；push 后等 60 秒用 `curl -L` 看真实返回。
3. 每次提交只做一件事，提交信息写「改了什么、行数怎么变」。
4. 推送前核「远端 head == 本地父提交」，`force=false`；冲突就重建本地历史，不 force。
