# 界面优化与后续模块规划

> 这份文件记的是一份**已定下的决定**，不是选项清单。原则一句话：
> **后端继续一个能力一个模块；前端不引构建工具，用 CSS 变量收敛而不是重写。**

## 一、现状判断（先看清再决定）

| 项 | 现状 | 结论 |
|---|---|---|
| 前端形态 | 10 个静态 HTML + 原生 ES module，无构建 | 保持。引框架会把「改一行 push 就上线」变成要装环境、要打包 |
| 样式 | `common.js` 共享逻辑，但每页的样式各写各的（admin 有独立 `admin.css`，其余页内联） | 收敛方向：抽公共样式变量，不追求全站统一重写 |
| 后台 | `admin.html` + `admin.js` + `admin.css` 三件套，11 个标签页（含「站点体检」「举报处理」） | 结构是好的，继续按「一个标签页 = 一个能力」加 |
| 后端 | 9 个领域模块 + 4 个 lib，`index.ts` 44 行纯装配 | 新能力一律新建模块，不再往入口里加路由 |

## 二、已经做了的（P0，本轮交付）

**「🩺 站点体检」标签页 + `modules/health.ts`**

把原先要靠外部脚本一条条 `curl` 才能确认的状态收成一页只读检查：

1. 站点配置里有没有密码哈希等敏感键（对应那次 `/api/settings` 泄露事故）
2. 门禁开关是否开启
3. 门禁口令是否还是出厂默认（服务端真做一次 PBKDF2 比对，只回结论不回哈希）
4. 管理员账号数是否为 0
5. 管理员是否还在用历史默认密码
6. 内容数据质量：未分类帖子 / 无封面游戏帖
7. 今日活跃与数据规模

验收：`GET /api/admin/health` 未登录 401；返回 `items[]` 每项带 `level: ok|warn|bad` 与一句人话。

## 三、P1 — 前端样式收敛（下一步优先做这个）

**问题**：同一套按钮/卡片/空态在 10 个页面里各写一份，改一处要动十处；颜色靠手抄 `#3b82f6`。

**做法（不自上而下重写）**：

1. 新建 `frontend/theme.css`，只放三样东西：
   - CSS 变量：主色 / 文字三级 / 圆角 / 阴影 / 间距（与现有取值完全一致，先保证「换了等于没换」）
   - 组件类：`.card` `.btn` `.btn-ghost` `.btn-danger` `.empty` `.tag`
   - 移动端断点变量
2. 迁移顺序：`admin`（已有 `admin.css`，先把它的字面量换成变量）→ `notifications` → `user` → `login` → `forum` / `game` 列表页 → 详情页最后。
3. 每迁一页，必须同步把该页 `?v=` 版本号 +1（手机缓存只认版本号）。
4. 验收标准：迁完的页面在 375px 与 1280px 下视觉与迁移前一致；`node --check` 过；控制台无报错。

**不做**：不改交互流程、不引入图标库、不改配色（换视觉是另一件事，等有明确想法再说）。

## 四、P2 — 举报与审核队列（已交付，2026-11-07）

社区站原来没有这条线，出问题只能靠管理员翻帖子。实际交付的版本与最初设想有两处差别，
都是落地时按现实条件改的，记在这里省得以后翻旧账：

**差别一：存储用 KV，不用 D1 表。**
原计划建 `reports` 表，但建表要走 D1 迁移，而本轮没有可用的部署通道（Windows 上 wrangler 跑不了，
迁移只能等外部部署 AI）。举报是低频、少量、按前缀就能列出来的数据，用已有的 `IMG_KV` 绑定正好零迁移上线。
代价：只支持按键前缀列举，不支持复杂查询与精确计数；工单保留 180 天（`expirationTtl`）。
如果以后举报量上来要做统计，再迁到 D1，接口形状不用变。

**差别二：目标只到帖子级（`post` / `game-post`），没做评论级。**
评论级举报需要把 comment 的父帖 id 也带上来，接口和列表都要多一层，收益不大；
真觉得某条评论有问题，举报帖子并写明位置一样能处理。留着以后加。

接口（`backend/src/modules/reports.ts`）：

| 方法 | 路径 | 权限 | 作用 |
|---|---|---|---|
| POST | `/api/reports` | 登录用户 | 提交举报；同一人对同一目标只留一条未处理工单 |
| GET | `/api/admin/reports?status=open\|done\|ignored\|all` | 管理员 | 列工单，时间倒序 |
| PATCH | `/api/admin/reports/:key` | 管理员 | 改状态 + 备注；只动工单，不动帖子 |

字段：`key / targetType / targetId / targetTitle / reason / reporter / reporterId / status / note / createdAt / handledAt / handledBy`。
理由上限 200 字，`targetType` 白名单两种，状态白名单三种。

前端：

- `frontend/report.js`（跨板块共享库，零第三方依赖）：自带样式的举报弹窗，五个预设理由胶囊（垃圾广告 / 违规内容 / 人身攻击 / 侵权盗图 / 与板块无关），
  深墨底 + 朱红强调，纸面与霓虹两种背景下都看得清；未登录点击直接引导去登录页，不让人填完才被拒。
- `post.html` / `game-post.html` 的 `.actions` 里各加一个 `⚑ 举报` 按钮，`window.reportCurrent()` 传 `targetType` 给该库。
- 后台第 11 个标签页「🚩 举报处理」：状态下拉 + 刷新 + 工单卡片（类型徽标、标题、状态色条、举报理由、举报人/时间、处理人/备注），
  三个动作「标记已处理 / 忽略 / 退回待处理」，可跳「查看原帖」新窗口打开。

边界（照旧）：**本模块不删帖、不封人**，只改工单状态。真正处置回「帖子管理 / 游戏站」做，避免一个按钮同时动两张表。

验证：`test_reports.cjs` 23 项全过（未登录 401、封禁账号 401、非法类型/理由 400、重复举报去重、非管理员 403、
非法状态 400、标记处理后队列减少、404 与非法编号），另 `test_app.cjs` 63 项、`test_gate.cjs` 50 项回归不变。

## 七、板块独立化（2026-11-07 起的新主线）

**目标**：每个板块（论坛 / 游戏 / 音乐 / 小说 / 影视 / 工具箱）都能单独存在、单独改、单独删，
删掉别的板块的样式和脚本不会伤到自己。**同时每个板块要有自己的视觉性格**，不是同一套模板换标题。

**结构判据（每个板块四个文件，互不越界）**：

| 文件 | 内容 | 依赖 |
|---|---|---|
| `<board>.html` | 只有该页的 DOM | 只引用下面三个 + `common.js` |
| `<board>.css` | 该页的全部样式（含自己的配色、字体、装饰） | 不 import 别人的 css |
| `<board>.js`（可选） | 该页独有的交互逻辑 | 不 import 别人的 js |
| `common.js` | 共享内核：请求、登录态、转义、Markdown、导航、显示设置 | 被所有页 import，**不改它的定位** |

结论：`common.js` 是"库"，不是"壳"。一个板块要能活，只需要 `自己的三件套 + common.js`，
不需要别的板块存在。跨板块只允许一种连接：普通 `<a href>` 跳转。

**各板块的视觉性格（已定，后续按此实现）**：

| 板块 | 视觉方向 | 主色 |
|---|---|---|
| 论坛 | 纸张感 / 阅读优先 / 楷体标题 | 墨蓝 + 米白 |
| 游戏站 | 霓虹 / 深色 / 强对比 | 紫青渐变 |
| 音乐 | 深蓝夜场 + 音符纹理（现已抽出 `music.css`） | 深蓝 + 电光蓝 |
| 小说 | 书卷 / 暖纸 / 衬线正文 | 棕 + 暖米 |
| 影视 | 影院黑 + 海报墙 | 黑 + 琥珀 |
| 工具箱 | 极简 / 灰白 / 高密度 | 中性灰 |

**落地进度**：

## 八、Spotify 接入（音乐板块，与原有播放器并存）

**技术选型**：用官方 **embed**，不做 OAuth / Web Playback SDK。

理由：SDK 那套要求 Premium 账号、在 Spotify 后台登记 redirect URI、并且要拿客户端凭据——
这个站没有构建步骤，密钥也不能放前端。embed 只需要一个公开链接，零凭据、零后端改动。

**实现**：`frontend/spotify.js`（零依赖，别的板块想用直接 import 即可）

| 导出 | 作用 |
|---|---|
| `parseSpotify(input)` | 纯函数，把网页链接（含 `/intl-xx/` 前缀与 `?si=`）、`spotify:type:id` 归一成 `{ type, id }` |
| `embedUrl(type, id)` | 生成 `open.spotify.com/embed/...`，带 `theme=0` 跟随明暗 |
| `mountSpotify(root)` | 绑到容器上：输入 → 载入 → 本地记住最多 8 项 → 标签切换 |

**边界**：

- 只做"听"，不做账号体系、不同步收藏、不读用户数据；
- 状态只存 `localStorage.kuhai_spotify_items`，与网易云播放器的 `music_playlist` / `music_now` 完全隔离，
  关掉这张卡片不影响原有播放；
- 国内直连 `open.spotify.com` 可能失败，面板里明确写了"先登录 Spotify"的提示，不做代理中转。

**验证**：`parseSpotify` 单测 11 条（5 种合法形态 + 5 种拒绝 + embedUrl 形态）全过；
`music.html` 内联脚本 `node --check` 过；`spotify.js` 需要的 5 个 id 全部存在于页面；
原有 13 个播放器 id 一个没少。

## 九、板块视觉身份（覆盖层做法）

每个板块的"个性"都写成**追加在 `xxx.css` 末尾的覆盖层**，不改动已抽出的原始规则：

- 好处一：抽样式那一步已经逐字符核对过，原始层是"已知正确"的基线，覆盖层出问题可以整段删掉回退；
- 好处二：页面里散落的内联样式（`display:none`、少量颜色）仍按原来的明暗假设工作，不会出现白条或黑字；
- 规矩：覆盖层开头写清楚这页的"性格"，用 `:root` 定义该页专属变量（如 `--seal`、`--neon-cyan`、`--cine-amber`），
  变量名按板块前缀区分，避免跨页复制时撞名。

## 六、执行纪律（每次都照这个走）

1. 改后端 → 新模块 + 在 `index.ts` 加一行挂载；`tsc` 诊断条数不许增加；补冒烟断言。
2. 改前端 → 同步 `?v=`；`node --check`；push 后等 60 秒用 `curl -L` 看真实返回。
3. 每次提交只做一件事，提交信息写「改了什么、行数怎么变」。
4. 推送前核「远端 head == 本地父提交」，`force=false`；冲突就重建本地历史，不 force。
